# Transaction pinning and replacement — synthetic mailing-list fixture

This is original test content shaped like a research summary, not an archived email or a claim about a particular author's position.

Transaction pinning describes cases where an adversarial transaction or descendant structure makes a preferred fee-bump transaction difficult to relay or mine under network policy. Replacement rules, descendant limits, package handling, and shared-transaction protocols can interact in subtle ways. A proposed mitigation needs an explicit attacker model and should separate mempool policy from consensus validity.

A careful mailing-list review would record the proposal version, Message-ID, replies, stated assumptions, unresolved objections, test vectors, and later revisions. Conclusions should be checked against the Bitcoin Core version whose policy is being discussed because relay behavior can change without a consensus soft fork.
